# juice-quickjs-bundle

`juice-quickjs-bundle.js` is a self-contained JavaScript bundle that runs the
[juice](https://github.com/Automattic/juice) CSS inliner inside a QuickJS engine
embedded in Perl (`JavaScript::QuickJS`). It lets Znuny inline modern CSS
(including `:is()`, `:not()`, child combinators and `::marker`) into article
HTML before sending an email, without requiring Node.js on the server at runtime.

The committed `juice-quickjs-bundle.js` is a build artifact. You only need to
rebuild it when upgrading juice or changing the inlining logic. Everything
needed to rebuild lives in `build_files/`.

## Contents of `build_files/`

- `entry.js` - bundle entry point. Imports the browser build of juice
  (`juice/client`, which omits Node-only file/resource loading) and exposes a
  global `inlineContent(html, css)` used from Perl.
- `shims.js` - provides globals that QuickJS lacks but juice/cheerio reference
  (`Buffer`, `process`, `atob`, `btoa`). These are injected into the bundle so
  the code parses and runs under QuickJS.
- `package.json` - contains build configuration and dependency declarations.
- `package-lock.json` - locks exact dependency versions for reproducible builds.

## Prerequisites

- Node.js **>= 22** (juice 12 requires it). Use `nvm` if your system Node is
  older:

  ```bash
  nvm install 22
  nvm use 22
  node --version
  ```

- The build must run from a directory that allows executing binaries.

## Build

```bash
cd build_files
# install build dependencies (juice + esbuild)
npm install
# produce the bundle one directory up
npm run build
```

The resulting `juice-quickjs-bundle.js` is a JS file. It
is read and evaluated by QuickJS from Perl.

## Verifying the build

The bundle must evaluate cleanly under QuickJS. If evaluation throws
`ReferenceError: 'X' is not defined`, QuickJS is missing a global that the
bundle references. Add a matching stub to `shims.js` and rebuild. Known ones
already handled: `Buffer`, `process`, `atob`, `btoa`.

A quick smoke test with a modern selector and a non-ASCII round-trip:

```bash
# requires Node >= 14 (the bundle uses modern syntax) - recommended to
# use the same Node >= 22 as for building
node -e '
  globalThis.Buffer = { isBuffer: () => false, from: (s) => s };
  const src = require("fs").readFileSync("juice-quickjs-bundle.js", "utf8");
  (0, eval)(src);
  const html = "<table class=\"t\"><tr><td>zażółć</td></tr></table>";
  const css  = ".t:not(.layout-table) td { border: 1px solid #000 }";
  console.log(inlineContent(html, css));
'
```

You should see the `<td>` receive an inline `border` and the text preserved.

Alternatively adjusted version of smoke test can be executed to check if it's working with
`JavaScript::QuickJS`:

```bash
# does not require Node, instead a perl module "JavaScript::QuickJS"
perl -MJavaScript::QuickJS -e '
    my $js = JavaScript::QuickJS->new;
    open my $fh, "<", "juice-quickjs-bundle.js" or die $!;
    local $/; my $src = <$fh>;
    $js->eval($src);
    $js->set_globals(
        HTML => q{<table class="t"><tr><td>zażółć</td></tr></table>},
        CSS  => q{.t:not(.layout-table) td { border: 1px solid #000 }},
    );
    print $js->eval("inlineContent(HTML, CSS)"), "\n";
'
```

## Notes

The bundle is regenerated by hand, not by the main CKEditor webpack build.
Rebuild and commit `juice-quickjs-bundle.js` whenever `entry.js`, `shims.js`,
or the juice version changes.

Specified files should be included when updating to new version:
- build_files/package.json
- build_files/package-lock.json
- build_files/entry.js
- build_files/shims.js
- juice-quickjs-bundle.js
- juice-quickjs-bundle.js.LEGAL.txt
- README.md

Do not commit `node_modules` folder as it's used locally.
